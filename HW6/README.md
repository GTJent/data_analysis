## 실행 방법

1. VS Code에서 `HW6` 폴더를 연다. `hw6.ipynb`, `sales_clean.csv`, `sales_model.pkl`, `app.py`, `README.md`는 같은 폴더에 둔다.
2. `hw6.ipynb`의 커널로 실습에 사용한 `data_analysis`의 `.venv`를 선택한다. 실습 환경은 Python 3.14.6, scikit-learn 1.9.1이다. 새 가상환경에서 실행한다면 `python -m pip install scikit-learn==1.9.1 pandas matplotlib joblib flask flask-restx ipykernel`로 필요한 패키지를 설치한다.
3. 노트북에서 **모두 실행**을 누른다. 마지막 셀의 `joblib.dump(lin2, "sales_model.pkl")`이 선택한 모델을 저장한다.
4. 노트북과 같은 가상환경을 활성화한 터미널에서 `HW6`를 현재 폴더로 두고 `python -m flask --app app run`을 실행한다.
5. [Swagger UI](http://127.0.0.1:5000/api/docs)에서 `POST /sales/predict`를 펼치고 **Try it out → Execute**로 요청한다. 실제 요청 주소는 `POST /api/sales/predict`이다.

요청 예시:

```json
{"quantity": 40, "unit_price": 200000}
```

성공 응답 예시 (`200 OK`):

```json
{"total_sales": 8000000}
```

## ①~③ 데이터 분할과 `qp`를 추가한 이유

`sales_clean.csv`의 1,004건을 학습용 803건과 테스트용 201건으로 나눴다(`test_size=0.2`, `random_state=0`). 세 모델을 같은 테스트 데이터에서 비교했다.

| 모델 | 입력 | 테스트 R² |
|---|---|---:|
| 선형회귀 | 수량, 단가 | 0.862 |
| 결정 트리(깊이 제한 없음) | 수량, 단가 | 0.994 |
| 선형회귀 + `qp` | 수량, 단가, 수량 × 단가 | 1.000 |

총액은 `수량 × 단가`다. 수량과 단가만 넣은 선형회귀는 `a × 수량 + b × 단가 + c` 형태여서 두 값의 곱을 그대로 표현할 수 없다. 곱을 `qp` 열로 만들어 추가하자 반올림한 계수는 `[0, 0, 1]`, 절편은 `0`으로 나왔다. 총액 공식과 같은 관계를 학습하면서 테스트 R²가 1.000이 됐다.

## ④~⑤ 비교용 결정 트리의 깊이 선택

같은 학습·테스트 분할에서 깊이를 바꾸며 잎 수와 R²를 확인했다. 깊이 3 이상인 후보는 전체 데이터에서 5겹 교차검증(`cv=5`)도 실시했다.

| `max_depth` | 잎 수 | 학습 R² | 테스트 R² | 5겹 교차검증 평균 R² |
|---|---:|---:|---:|---:|
| 1 | 2 | 0.361 | 0.346 | — |
| 2 | 4 | 0.739 | 0.711 | — |
| 3 | 8 | 0.876 | 0.846 | 0.845 |
| 5 | 32 | 0.972 | 0.961 | 0.961 |
| 8 | 250 | 0.998 | 0.991 | 0.992 |
| 12 | 781 | 1.000 | 0.994 | 0.995 |
| 제한 없음 | 800 | 1.000 | 0.994 | 0.995 |

비교용 트리로 **깊이 8**을 선택했다. 깊이를 8에서 12로 늘리면 잎 수가 250개에서 781개로 세 배 이상이 되지만, 교차검증 평균 R²는 0.992에서 0.995로 0.003만 높아졌다.

## ⑥~⑦ 주문 한 건의 예측과 API 모델 선택

수량 **40개**, 단가 **200,000원**인 주문을 두 모델에 입력하고 직접 계산한 총액과 비교했다.

| 계산 방법 | 총액(원) |
|---|---:|
| 선형회귀 + `qp` | 8,000,000 |
| 결정 트리(깊이 8) | 7,362,301 |
| 직접 계산: 40 × 200,000 | 8,000,000 |

API에는 **선형회귀 + `qp`**를 사용했다. 이 모델은 테스트 R²가 1.000이었고 예시 주문에서도 실제 총액과 일치했다. 깊이 8의 결정 트리는 같은 주문의 총액을 637,699원 낮게 예측했다.

클라이언트는 `quantity`와 `unit_price`만 보낸다. `app.py`가 `qp = quantity × unit_price`를 계산한 뒤 학습할 때와 같은 순서(`quantity`, `unit_price`, `qp`)로 모델에 넣고, 예측 금액을 정수로 반환한다. 이 과제에서는 모델을 저장하고 API에 연결했지만, 총액 공식이 정해진 실제 서비스라면 두 값을 직접 곱하는 편이 더 간단하다.
